# 08 — Criterios de aceptación

## Integración

- [ ] `/portfolio-2026` abre directamente y después de recargar.
- [ ] La página anterior conserva diseño y funcionamiento.
- [ ] No hay errores de consola.
- [ ] Build y lint finalizan correctamente.

## Contenido

- [ ] Se muestra “Stefany Aguiar”.
- [ ] Se usa el descriptor profesional correcto.
- [ ] Solo aparecen los tres proyectos seleccionados.
- [ ] No se inventaron tarifas, contactos, testimonios ni credenciales.
- [ ] El contenido está centralizado y es fácil de modificar.

## Dirección visual

- [ ] La experiencia se percibe como un portfolio físico/editorial.
- [ ] El titular usa una fuente sobria y menos alta que el mockup inicial.
- [ ] Papel, planos, calcos y terracota forman un sistema coherente.
- [ ] No parece una plantilla SaaS ni un conjunto de cards.
- [ ] Las imágenes conservan calidad y proporción.

## Animación

- [ ] La portada abre con origen correcto en el lomo.
- [ ] Existe al menos una transición convincente de página.
- [ ] La hoja de calco revela contenido o conecta escenas.
- [ ] Las timelines responden al scroll y funcionan al invertir dirección.
- [ ] No hay saltos notorios al entrar o salir de escenas pinned.
- [ ] No quedan ScrollTriggers activos al desmontar.

## Calculadora y contacto

- [ ] La calculadora permite completar la configuración mínima.
- [ ] Tarifas y multiplicadores están centralizados.
- [ ] Se aclara que el resultado es orientativo.
- [ ] El CTA transmite o conserva la configuración.
- [ ] El formulario valida y muestra estados de éxito/error.

## Responsive y accesibilidad

- [ ] Desktop, tablet y mobile tienen composición útil.
- [ ] Mobile usa una hoja legible en lugar de dos páginas diminutas.
- [ ] La página puede recorrerse con teclado.
- [ ] El foco es visible.
- [ ] `prefers-reduced-motion` conserva todo el contenido y las acciones.
- [ ] Los controles táctiles tienen tamaño adecuado.

## Rendimiento

- [ ] Solo se precarga el asset visual crítico.
- [ ] Imágenes posteriores usan lazy-loading cuando corresponde.
- [ ] No hay layout shift evidente.
- [ ] No se agregaron dependencias pesadas sin justificación.
- [ ] La experiencia se mantiene fluida en un equipo medio y en mobile.
